**Classification:** TLP:AMBER  
**Environment / Platform:** Active Directory / Windows Enterprise Workstations / HTB Sherlock  
**Target:** Forela-Wkstn001.forela.local / Network Traffic and NTLM Authentication  

#### 1. Incident Scenario, Context, and Identification

- **Executive Summary:** A SIEM alert triggered by a network authentication anomaly was investigated: an explicit discrepancy between the source IP address and the reported workstation name during logon. Forensic correlation between network traffic (ntlmrelay.pcapng) and audit logs (Security.evtx) confirmed an **NTLM Relay** attack. The adversary operated from an unauthorized rogue device (172.17.79.135), intercepting network requests generated by the victim account (arthur.kyle) on Forela-Wkstn002 after coercing it into accessing a non-existent shared resource (\\DC01\Trip). The attacker relayed the cryptographic NTLMv2 challenges and responses against Forela-Wkstn001 (172.17.79.129), successfully authenticating and accessing the IPC$ share.
    
- **Telemetry Sources and Evidence:**
    
    - ntlmrelay.pcapng: Packet capture analyzed using Wireshark/tshark (NBNS, SMB, SMB2, KRB5 protocols).
        
    - Security.evtx from Forela-Wkstn001: Event ID 4624 (Network Logon - Type 3) and Event ID 5140 (Network Share Access).

#### 3. Infection Chain and Detailed Forensic Analysis

- **Forela-Wkstn001 (Relay Target):** **172.17.79.129** (Identified through large volumes of incoming traffic and NetBIOS/SMB records).
    
- **Forela-Wkstn002 (Legitimate Source Host):** **172.17.79.136** (Identified via NBNS broadcast requests).
    
- **Hostile Device (Rogue Asset):** **172.17.79.135** (Intermediary host running the relay suite, e.g., ntlmrelayx).
    

1. **SMB Traffic Generation:** The victim user account arthur.kyle initiated a connection to network path **\\DC01\Trip**.
    
2. In the packet capture, these requests consistently failed with the error **STATUS_BAD_NETWORK_NAME**, confirming that the host was induced to access an unreachable share to force an authentication fallback and enable NTLMv2 challenge relaying.
    

On Forela-Wkstn001, the realized access was logged via Event ID 4624:

- **UTC Timestamp:** **2024-07-31 04:55:16.240589Z** (Record ID 14610).
    
- **TargetUserName:** **arthur.kyle** (SID S-1-5-21-3239415629-1862073780-2394361899-1601).
    
- **LogonType:** 3 (Network Logon).
    
- **AuthenticationPackageName:** NTLM (LmPackageName: NTLM V2).
    
- **Critical Forensic Discrepancy:**
    
    - **WorkstationName:** **FORELA-WKSTN002**
        
    - **IpAddress (Actual Traffic Source):** **172.17.79.135**
        
    - This mismatch between the hostname specified during NTLMSSP negotiation and the IP address establishing the underlying TCP socket conclusively demonstrates that the session was relayed by a third party (172.17.79.135).
        
- **Source Port:** **40252**.
    
- **Assigned LogonId:** **0x64a799**.
    
- **Accessed Shared Resource (Event ID 5140):** The attacker immediately accessed the IPC$ share (`\\*\IPC$`), a standard mechanism used by SMB-based remote execution tools (such as Impacket) to enumerate Named Pipes prior to deploying remote services or tasks.

#### 5. Containment, Eradication, and Hardening Plan

1. **Switch Port Isolation:** Trace the physical switch port or MAC address linked to rogue IP 172.17.79.135 and revoke its network connectivity (802.1X quarantine/port disable).
    
2. **Session Termination:** Terminate active network session 0x64a799 on Forela-Wkstn001 and reset the password for user account arthur.kyle.
    
3. **Mandatory SMB Signing:**
    
    - Enforce digital signing across all domain clients and servers via GPO:  
        Microsoft network server: Digitally sign communications (always) = Enabled.  
        Microsoft network client: Digitally sign communications (always) = Enabled.  
        (This completely mitigates NTLM Relay attacks targeting SMB).
        
4. **Extended Protection for Authentication (EPA):** Enable EPA on internal web services and management interfaces to prevent relaying toward HTTP/HTTPS/LDAP.
    
5. **Deprecate NTLMv1 and Restrict NTLMv2:** Transition the domain infrastructure toward pure Kerberos authentication and disable NTLM fallback wherever viable.
